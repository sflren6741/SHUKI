# 📰 ニュースの登録元を対話で増やす・見直す

SHUKIのニュースは毎朝、購読フィードの新着から AI が重要なものを選んで `/news` に並べる。何を購読しているかで中身が決まるので、このスキルは**登録元そのもの**を扱う。記事の選定・評価は対象外（それは `news_fetch.py` と /news の 良かった／外れ）。

## 道具（必ずこれを使う。feeds.json を手で書き換えない）

```powershell
$py = '<scripts>\.venv\Scripts\python.exe'; $ns = '<scripts>\news_store.py'
& $py $ns feeds                                   # 一覧＋フィードごとの 良かった/外れ 件数
& $py $ns feed-check '<url>'                      # 1回だけ取得して記事数・題名を確認（保存しない）
& $py $ns feed-add '<url>' --category '<カテゴリ>' [--name '<名前>']   # 確認してから登録（既定 via=ai）
& $py $ns feed-remove '<url>'
& $py $ns watches                                 # 進行中のウォッチ
& $py $ns watch '<話題>' [--expires YYYY-MM-DD]   # 既定30日
& $py $ns watch-stop <id>
```

- 失敗時は `{"error": ...}` を出して終了コード1。公開ホスト以外・RSS/Atomでないページ・記事0件・重複は登録できない。
- 変更は `/news/sources` に返答終了時に自動で反映される（ページを開いていれば再読み込み不要）。

## 起動テキストで分岐

| テキスト | モード |
|---|---|
| テーマ・話題（例「ドイツのエンジニア転職市場」） | A. 探して追加 |
| URL | C. そのURLを追加 |
| `review`・「見直し」 | B. 見直し |

### A. 探して追加

1. `feeds` で現状を見る（同じサイトの重複・既存カテゴリ）。
2. WebSearch / WebFetch で候補を探す。サイトの `<link rel="alternate" type="application/rss+xml">`、`/feed` `/rss` `/atom.xml`、はてな・Qiita・Zenn のタグフィード等。
3. **候補は全部 `feed-check` に通し、取得できたものだけを出す**（URLを推測で書かない）。
4. 2〜5件を短い表で見せる：名前／何が流れてくるか（feed-check の題名と最近の記事から）／言語／更新の多さ／入れるカテゴリ（**既存カテゴリを優先**、新設は必要な時だけ）。おすすめを1つ示す。
5. RSSが見つからない話題・「一度だけ知りたい」ことは、フィードの代わりに**ウォッチ**を提案する。
6. ユーザーが選んだものだけ `feed-add` / `watch` する。選択肢は `NTFY_CHOICES` で出す（例：`1と3を追加|全部追加|追加しない`）。
7. 何を登録したかを1〜2行で報告する。

### B. 見直し

1. `feeds` の ratings を見て、**外れが良かったを上回る**フィード・**評価が1件も無い**フィードを挙げる（件数を根拠に。推測で「質が低い」と言わない）。
2. 外す／カテゴリを変える（＝外して追加し直す）候補を出し、ユーザーの選択後に実行する。
3. 期限切れが近いウォッチ・もう不要そうなウォッチがあれば添える。

### C. URLを直接渡された

`feed-check` → 通ればカテゴリだけ確認して（明らかなら確認不要）`feed-add`。サイトのページURLだった場合はそのページからフィードURLを探して確かめる。

## 守ること

- 購読は1日の選定入力を増やす（1フィードあたり最大5件の候補）。**合計25件前後を超えそうなら**、追加と同時に外す候補も示す。
- ウォッチは毎朝 Web 検索で探す。定期便が Codex で動いている日は検索できず保留されるので、急ぐ話題ならそう伝える。
- AGENTS.md の代筆禁止ゾーン・読めない領域に関わる話題をウォッチ・フィードにしない。
- Codex など WebSearch が無い環境では A の探索はできない。ユーザーが渡したURLの C だけ行い、探索は「Claude 側で実行が必要」と伝える。
