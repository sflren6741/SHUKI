# 🎯 今やる一手（next）

「やる気を出す」ためのスキルではない。**着手の手前にある「決定」と「重さ」をAIが肩代わりして、最小の一歩だけ差し出す** スキル。ユーザーに感情を書かせない・選ばせない。AIが読む・選ぶ・翻訳する側に全部寄せる。

> 背景：先延ばしは意志の弱さではなく、タスクへの抵抗感が原因。締切が迫る→先延ばし→罪悪感→さらに抵抗感が増す、の悪循環に入る前に断つ。詳細根拠 → [[タスクへの抵抗感を仕組みで減らす]]（概念ノード・あれば）

## 起動方法

- `/next` — 今やる一手を1つ出す
- `/next 5分` / `/next 30分` — その時間でできるタスクに絞る（時間指定）
- `/next <Area名>` — 指定 Area のタスクに絞る
- `/next 軽いの` — 一番軽い・着手コストの低いものを出す
- `/next なぜ <タスク>` — なぜモード。指定タスク（省略時は直前に出した一手）の目的・メリット・背景を対話で深めて `## なぜやるか` に書き足す

ユーザーが一手を見て「重い」「なんでこれやるんだっけ」と漏らしたら、説得せず**なぜモードに切り替える**（§6）。

## 🧭 必読コンテキスト

開始前に以下を読む：

- `00_Intranet/AI運用ルール集（イントラ）/デザイン言語.md` — トーン（内省・押し付けない）
- `00_Intranet/AI運用ルール集（イントラ）/哲学・価値観.md` — 判断軸

（軽量スキルなので Identity 全文は任意。トーンだけ外さない）

## 📋 フロー

### 1. タスクを読む

```
Glob: 04_Tasks/タスク管理/タスク/*.md
```

各ファイルの frontmatter から抽出：`status` / `priority` / `due` / `area` / `completion_criteria` / 本文の「次の一歩」系メモ。

**対象**：`status: todo` または `status: in-progress` のみ。`done` / `on-hold` / `cancelled` / `archived` は除外。**`start` が未来の日付のタスクも除外**（意図的な先延ばし中＝ユーザーが「その日まで手を付けない」と決めたもの。候補に出して罪悪感を起こさせない・フォーカス・ファネル原則）。
引数で Area・時間が指定されていれば、その軸で絞る。

**予定との衝突チェック（軽く）**：`<workspace>\gcal_today.md` があれば読む。直近1時間以内に固定予定が迫っているなら、重いタスクではなく**その隙間で終わる軽い一手**を選ぶ（ファイルが無ければスキップ・ユーザーに聞かない）。

**🃏 今月のフォーカス概念（あれば・2026-07-21導入）**：`<scripts>\concept_game\data\decks.json` の `active:true` デッキの `cards`（概念名の配列、最大7件）と、`<scripts>\board_quests.json` の各タスクエントリが持つ `concepts` 配列の積集合を取り、「フォーカス概念に紐づくタスク stem 集合」を作る。ファイルが無い／アクティブデッキが無い／積集合が0件のいずれかなら、この節は使わずそのまま §2 の通常選定に進む（無理にフォーカスを持ち出さない）。

### 2. 「今やる一手」を1つ選ぶ

並べない。**1つだけ**選ぶ（決定麻痺＝「どれに手を付けるか分からない」を消すのが目的）。

選定の重みづけ（上から優先）：

1. **今日〜数日で動かないと本当にまずいもの**（締切が近い、かつ放置で被害が出る）
2. **着手さえすれば軽いもの**（5〜15分で完了 or 前進できる）— freeze 解除に効く
3. **重く見えて止まっているが、最初の一歩は小さいもの**（分解して出す）
4. 優先度 `高`
5. **フォーカス概念に紐づくタスク**（上記の積集合に入っているもの）— 1〜4が同点・僅差の時のタイブレークとして一段引き上げる。締切の緊急度を覆してまで優先はしない（1〜3が明確に勝る時はそちらを出す）

> ⚠️ 「一番締切が近い＝一番怖いタスク」をいつも出さない。手が止まっている時に最も効くのは、**今ここから実際に動ける小さい一手**。怖いタスクは §4 のフレーミングで「最初の5分」に割って出す。

### 3. 出力（1件・短く）

```markdown
## 🎯 今これ

**<タスクタイトル>**（<Area> / 目安 <N>分）

→ **最初の一歩**：<今すぐ取れる最小の具体アクション1つ>

なぜ：<目的・できたら何が嬉しいか・1〜2行>
```

- **最初の一歩は「今すぐ・5〜10分で・迷わず手が動く」粒度**まで割る（例:「ホテル予約」ではなく「Booking で候補3件をタブで開くだけ」）
- タスク本文に既にスモールステップがあるなら、その**先頭の1つだけ**を出す（ユーザーが既にやっている分解を活かす。全部並べない）
- **「なぜ」の出し方**：タスクに `## なぜやるか` セクションがあれば、そこから**目的・メリットを1〜2行に凝縮して載せる**（やらされ感→「自分がやりたかったこと」への再接続）。締切や優先度だけの機械的な「理由」にしない
- `## なぜやるか` が**無いタスク**を出した時は、なぜ行は仮の1行に留め、末尾に「このタスクの『なぜ』はまだ薄い → `/next なぜ` で深める？」と1行添える（強制しない）
- 出したタスクが §1 で作ったフォーカス概念の積集合に入っている時は、なぜ行の末尾に「🎯 今月のフォーカス概念『〈概念名〉』を鍛える一手」を1行添える（`## なぜやるか` の代わりではなく追加。フォーカスでない時は何も足さない）

### 4. 罪悪感ループを断つフレーミング（締切が過ぎた/迫ったタスクを出す時）

締切オーバー・遅れているタスクを選んだ時は、**責める言い方を絶対にしない**。再起点として翻訳する：

- ❌「期限切れ。早くやって」「もう3日遅れてる」
- ✅「これは今日から仕切り直せる。まず5分だけ触ろう」「重く見えてるだけで、最初の一歩は<小さい行動>」

期限は**カウントダウンや赤アラートで煽らない**（スタンドアップ §2 とは役割が違う。こちらは着手を助ける側）。「遅れ」を強調せず「ここから動ける」に寄せる。

### 5. 出した後の選択肢（1行で添える）

- 「重すぎ？ → もっと小さく割るよ」
- 「これじゃない気分？ → 別の一手を出す」
- 「時間ない？ → `/next 5分` で軽いのだけ出す」

ユーザーが「別の」と言ったら §2 に戻って次点を出す。**説得しない・粘らない**（押し付けはトーン違反）。

## 🔎 §6 なぜモード（タスクを意味に再接続する対話）

`/next なぜ <タスク>`、または一手を見たユーザーが「重い」「なんでこれやるんだっけ」と漏らした時に入る。

**狙い**：抵抗感の根っこは「これ何のためにやるんだっけ」が抜け落ちて、ただの作業に見えること。目的・達成感・メリット・背景を**ユーザーの言葉で**戻すと、やらされ仕事が「自分がやりたかったこと」に変わる。**書く負担はAIの問いが肩代わりする**（ユーザーは短く答えるだけ）。

### 対話のしかた

問いは **1ターンに1つ**。ユーザーの答えは短くてOK。深追いしない。以下を順に（既に答えが出た項目は飛ばす）：

1. **目的**：「これ、何のためにやりたいんだっけ？」
2. **できたら / メリット**：「できたら何が嬉しい？ 何が変わる・前に進む？」
3. **背景**：「いつ・なんでやろうと思ったやつ？」（→ ログ・価値観・人・Project に繋がる手がかり）

- ユーザーが言葉に詰まったら、こちらで仮説を出して「こういう感じ？」と確認する（言い換えで上書きはしない）
- 答えが「特にない／義務でやるだけ」なら、それも事実として受け取る。無理に意味を捏造しない（→ そのタスク自体が要る？を `/audit-tasks` に渡す選択肢を添える）

### 書き込み

対話で出たものを、対象タスクの本文に `## なぜやるか` セクションとして **Write/Edit で追記**する（ユーザーの言葉を使う・AIが盛らない）。既にあれば更新。

```markdown
## なぜやるか
- **目的**：<何のために>
- **できたら**：<達成イメージ・どんな状態になるか>
- **メリット**：<得られるもの>
- **背景**：<いつ・なんでやりたいと思ったか>　関連: [[関連ログ or 価値観 or 人 or Project]]
```

- **背景の wikilink を必ず1つ以上探す**：対話で出た出来事・価値観・人・Project を vault 内で照合し、`[[...]]` で繋ぐ（2層リンク戦略・本文内 wikilink は明示的関連がある時のみ）。該当が見つからなければ無理に張らない
- 書き込みは **`## なぜやるか` 本文のみ**。frontmatter の `status` / `priority` 等メタデータは触らない（着手・完了の記録はユーザー or orchestrator）
- 追記後、「次はこれを最初の一歩から始める？」と §3 の一手に戻れるよう橋渡しする

## 原則

- **1ターン1タスク**。候補を3つ4つ並べて選ばせない（それ自体が決定麻痺の素）
- **書かせない**。感情ラベリングや状態入力をユーザーに求めない。AIが勝手に読んで出す
- **励まさない**。「頑張ろう」「君ならできる」は言わない（デザイン言語・アンチスロップ）
- **完了させなくていい**。「着手した」で勝ちとする。一歩出たら深追いしない
- **タスクDBへの書き込みは `## なぜやるか` 本文の追記だけ**（なぜモード時）。frontmatter の status / priority / 完了の書き換えはしない（着手・完了の記録はユーザー or orchestrator）
- 適切なタスクが0件なら「今は余白。やるべき緊急はない」と正直に出す（無理に絞り出さない）
