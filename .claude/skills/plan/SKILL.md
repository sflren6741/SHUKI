# 🗺 プラン（戦略設計スキル）

## 起動方法

- `/plan <目標>` — 目標指定で開始（例: `/plan IELTS Band 7 を10月に取る`）
- `/plan` — 目標なしで開始 → 最初に「何を達成したい？」と聞く

## 🧭 必読コンテキスト

開始前に以下を読む：

- `00_Intranet/AI運用ルール集（イントラ）/🪪 Identity.md`
- `00_Intranet/AI運用ルール集（イントラ）/哲学・価値観.md`
- `00_Intranet/AI運用ルール集（イントラ）/デザイン言語.md`
- `00_Intranet/AI運用ルール集（イントラ）/🗂 vault構造ガイド.md` — Project / Task の構造と命名規則

---

## 🎯 このスキルの目的

**「やりたいこと」を「実行できる構造」に変える収束フェーズ専用。**

- @researcher（旧 @planner）は「具体的に調べる」担当
- `/discuss` は「思考を広げる」担当
- `/plan` は「目標を構造に変換する」担当

---

## フロー

### ① 目標のヒアリング

以下を1問ずつ確認する（一気に聞かない）：

1. 目標の一言表現（「○○を達成する」の形式で確認）
2. 期限（具体的な日付 or 「未定」）
3. 今どのくらい進んでいるか（ゼロから？何かやってる？）
4. 一番の制約・ブレーキは何か（時間・お金・スキル・情報不足 etc.）
5. 完了条件（「何ができたら達成と言えるか」）

### ② マイルストーン案の提示

ヒアリング後、3〜5つのマイルストーンを提示する。

フォーマット：
```
## マイルストーン案

| # | マイルストーン | 目安時期 | 成功指標 |
|---|---|---|---|
| 1 | <最初の一歩> | <日付目安> | <具体的な完了条件> |
| 2 | <次のステップ> | <日付目安> | <具体的な完了条件> |
...

## 前提・リスク
- <前提になっていること>
- <想定リスクと対処>
```

ユーザーが確認・修正したらステップ③へ。

### ③ タスク分解の確認

「最初のマイルストーンに向けて、今週できる最小のタスクを3つ出しますか？」と聞く。

Yes なら、タスク案を提示：
```
- <タスク1>（目安: 30分）
- <タスク2>（目安: 1時間）
- <タスク3>（目安: 2時間）
```

### ④ 出力の確認

「Project ファイルとタスクを作成しますか？」と聞く。

**Yes の場合**：

**Project ファイル作成**（`03_Projects/プロジェクト/<プロジェクト名>.md`）：

```markdown
---
title: "<プロジェクト名>"
type: project
area: <該当 Area>
status: in-progress
date: YYYY-MM-DD
created: YYYY-MM-DD
---

# 🗺 <プロジェクト名>

## 目標
<一言で何を達成するか>

## 完了条件
<何ができたら達成と言えるか>

## 期限
YYYY-MM-DD

## マイルストーン

| # | マイルストーン | 目安時期 | 状況 |
|---|---|---|---|
| 1 | <マイルストーン> | YYYY-MM | ⬜ |
| 2 | <マイルストーン> | YYYY-MM | ⬜ |

## 制約・リスク
- <制約>

## 関連タスク

```base
filters:
  and:
    - file.inFolder("04_Tasks/タスク管理/タスク")
    - parent.contains("<プロジェクト名>")
    - status != "archived"
views:
  - type: table
    name: 関連タスク
```

## メモ
```

**タスクの作成**（承認されたタスク分は `04_Tasks/タスク管理/タスク/<タイトル>.md`）：

タスクは「最小の作業」ではなく、進捗と品質を別々に確認できる**最小の成果単位（レビュー単位）**で切る。ファイルを開く・読む・編集する等の単純な手順は本文に残し、独立した成果・決定・検証結果だけをタスクにする。

```markdown
---
title: "<タスクタイトル>"
status: todo
area: <Area>
parent: "[[<プロジェクト名>]]"
due: YYYY-MM-DD
created: YYYY-MM-DD
date: YYYY-MM-DD
agent: ""
---

# <タスクタイトル>

## やること
<具体的な作業内容>

## 完了条件
<何ができたら done にするか>

## 結果・レビュー
- 証拠:
- レビュー: pending
- 未解決:
- 次の一手:
```

### ⑤ @researcher への引き継ぎ（必要な場合）

「具体的な情報収集（価格・比較・ルート）が必要なら @researcher に調べてもらいますか？」と聞く。

Yes なら：タスクを `agent: researcher` で作成し（`human_only` は書かない）、@researcher がピックアップする形にする。

---

## @researcher との差分まとめ

| | `/plan` スキル | `@researcher` エージェント |
|---|---|---|
| 役割 | 目標の構造設計 | WebFetch による具体的調査 |
| 入力 | 「こうなりたい」 | 「これを調べてほしい」 |
| 出力 | Project ファイル・タスク | 比較表・旅行プラン・価格一覧 |
| 実行モード | 対話（手動） | 自動ピック可 |

---

## 代筆禁止の継承

相手との将来計画（結婚・同棲等）についての計画立案は可。ただし「パートナーへの話し方」「プロポーズの文句」等の代筆はしない。

- アンチスロップ: <「ぜひ頑張りましょう」等のフィラーが混入していないか>
