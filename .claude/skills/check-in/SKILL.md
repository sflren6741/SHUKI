# 🪞 チェックイン（自己点検スキル）

## 起動方法

- `/check-in` — 通常モード（5分のパルスチェック）
- `/check-in ログ分析` — ログ分析モード（旧 @self-analysis 機能）
- `/check-in <Area名>` — 指定 Area に絞ったパルスチェック

## 🧭 必読コンテキスト

開始前に以下を読む（すべて必須）：

- `00_Intranet/AI運用ルール集（イントラ）/🪪 Identity.md`
- `00_Intranet/AI運用ルール集（イントラ）/哲学・価値観.md`
- `00_Intranet/AI運用ルール集（イントラ）/デザイン言語.md`

## 🅰 通常モード（5分パルスチェック）

### フロー

1. **Area の選択**（最初に聞く）
   - 「今どのAreaについて話したい？」
   - または「全体的に今どう？」
   - 10 Area: 非公開Area / 人間関係 / 自己理解 / 仕事 / 英語 / ハンドボール / 健康 / 娯楽 / お金 / 時間管理

2. **パルスチェック**（3〜5問）
   - 状態を引き出す問い：「最近どんな気分？」「今一番気になってることは？」「うまくいってることは？」
   - **体調の問いを1つ含める（2026-07-04 ユーザー採用・健康 Area の観察点）**：「最近眠れてる？体調はどう？」程度に軽く。受診予定（通院等）が話に出たらタスク化を提案する。医学的助言はしない（健康は人間確認ゾーン）
   - **感情の問いを1つ含める（2026-07-04 ユーザー採用）**：「最近いちばん感情が動いたのは？」程度に軽く。出てきた瞬間はセッション末の情報抽出でログ候補に含める（→ 概念 [[感情が動くことを大事にする]]）
   - 深追いしない。答えを短くてもOK
   - 評価や指示は出さない（聞く・受け取る）

3. **セッション末 情報抽出（毎回・必須）**

   会話を振り返り、以下を自動スキャンして一覧化する。ユーザーに確認してから保存する。

   | 種類 | 抽出対象 | 保存先 |
   |---|---|---|
   | タスク | 「〜したい」「〜やらないと」「〜取得する」等の行動意図 | `04_Tasks/タスク管理/タスク/` |
   | ログ | 気づき・状態・出来事 | `07_Logs/ログ/` |
   | リソース | 目標・原則・学び | `06_Resources/Resources/ナレッジ/` |

   手順：
   1. 抽出結果を箇条書きでユーザーに見せる（「これを保存してよいか？」）
   2. 承認後に Write / Edit で一括作成
   3. ログはユーザーが「ログに残す」と言ったものだけ作成（強制しない）

4. **セッション末の選択肢**（情報抽出の後に提示）
   - 「もっと深く掘りたい？」→ `/discuss` へ誘導
   - 「最近ログを書いたなら分析する？」→ ログ分析モードへ

### 原則

- 「大丈夫ですよ」「うまくいってます」等の根拠なき肯定をしない
- ユーザーが答えた言葉をそのまま使う（言い換えない）
- 問いは1ターンに1つ

## 🅱 ログ分析モード

`/check-in ログ分析` または通常モード末尾で「ログ分析する？」を選んだ場合。

### フロー

1. **対象範囲の確認**
   - 「直近何日分を見る？（デフォルト：30日）」
   - または「テーマを指定する？（例：仕事のストレス・相手とのこと）」

2. **ログの読み込み**
   ```
   Glob: 07_Logs/ログ/*.md
   Read: date が範囲内のファイルを読む（最大15件）
   Grep: キーワード（感情語・繰り返しテーマ）で絞り込み
   ```

3. **パターン抽出**（3つ以内）
   各パターンは以下の3段構成：
   1. ユーザーの言葉を引用（「」で囲む）
   2. 観察：「〜かもしれない」と仮説として書く（断言しない）
   3. 問い：次の問いを1つだけ

4. **早期警告サイン**（あれば）
   「○○が続くときは△△が起きやすい」等、具体的に。

5. **出力の保存**（任意）
   - 「このレポートを保存する？」と聞く
   - Yes → `07_Logs/ログ/内省パターン/<YYYY-MM-DD>.md` に Write

### 分析の原則（引き継いだ制約）

- ❌ ログ本文を書き直さない（Read のみ）
- ❌ 「あなたは○○という人です」と断定しない
- ❌ 心理学の診断名・用語をラベルとして貼らない
- ❌ 「大丈夫です」等の根拠なき肯定をしない
- ❌ 相手とのやり取りの詳細を本人の許可なく要約に含めない
- ✅ ユーザーの言葉づかいで（話し言葉、主語「俺」OK）
- ✅ 解釈は仮説として提示

### 出力フォーマット（保存時）

```markdown
---
title: "内省パターンレポート YYYY-MM-DD"
type: "📜原則・ルール"
area: 自己理解
date: YYYY-MM-DD
created: YYYY-MM-DD
---

# 🪞 内省パターンレポート — YYYY-MM-DD

## 分析期間
<対象ログの範囲>

## パターン 1：<テーマ名>

> 「<ユーザーの言葉を引用>」（<ログ日付>）

**観察**：<パターンの記述。「〜かもしれない」と仮説として書く>

**問い**：<次の問いを1つ>

---

## パターン 2：<テーマ名>

（同上）

---

## 早期警告サイン（あれば）
<「○○が続くときは△△が起きやすい」等、具体的に>
```
