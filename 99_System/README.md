# 99_System — 機械ゾーン（人間は普段開かなくてよい）

AI・スクリプトの作業領域。ここに溜まる実行ログ・QAレポート・稼働サマリー・状態ファイルは、**人間が直接読むことを前提にしていない**。人間向けの情報は、朝スタンドアップ（`07_Logs/朝スタンドアップ/`）や `/ops-review` スキル経由で届く設計。

> このフォルダの**中身は `.gitignore` で除外**され、公開リポジトリにはこの README だけが含まれる。あなたの環境で稼働し始めると各サブフォルダが自動生成される。

## サブフォルダ

| パス | 役割 |
|---|---|
| `99_System/agent-runs/` | エージェント実行ログ。**`.log` 一本化**：履歴の実体は日次 `<系統>_YYYY-MM-DD.log`（1日1ファイル・全文）。「履歴を見る」＝その日の `.log` を開く |
| `99_System/monitoring/` | 稼働サマリー・運用改善提案（`運用改善提案.md` に週次で追記） |
| `99_System/qa/` | `vault_lint.py`（決定的QA・毎日）の日次レポート置き場（日付別・朝の orchestrator がトリアージ） |
| `99_System/tutorial-progress.md` | `/tutorial` スキルの進捗ファイル（章立てツアーの中断・再開に使う） |

## なぜ分けるのか

「要らないものを、見える場所に置かない」ため。ログ・レポート・状態ファイルが PARA の人間ゾーン（00〜08）に散らばると、Obsidian を開くたびに機械の生成物が目に入って認知負荷になる。機械の作業物は 99_System に隔離し、**人間には要約だけを届ける**。

## アーカイブとの関係

99_System は「まだ生きている機械の作業領域」。役目を終えた設定・スクリプト・議論メモは `08_Archive/` へ物理移動する（判断基準は `CLAUDE.md` §アーカイブ運用）。
